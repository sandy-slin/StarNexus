# 阶段二：董事长 / CEO 设计（2.0.0）

## 一、现在有什么

`bridge/fleet/ceo.py` 是一个能跑通的原型，11-14 以来跑过 5 次任务（2 次交付、1 次问人后交付、2 次被叫停）：

- 在群里发 `/ceo 群` 把一个群设成 CEO 群；之后群里说的话就是总任务。
- CEO 大脑：Claude，不给任何工具，只输出 JSON（拆分 / 复核）。
- 一次最多拆 4 个子任务，并行开会话（Claude 或 Codex），最多复核 3 轮：继续派指令 / 问董事长 / 交付。
- 子任务会话照常出现在会话总览里，但**没有自己的群**；CEO 群里只有 CEO 发的文字消息。

原型的问题（从用户角度）：

1. **看不见子任务**：子任务在跑时，董事长在 CEO 群里只能看到「CEO 分工」和最后的「交付」，中间几分钟到几十分钟没有任何东西；想看某个子任务只能去会话总览里翻。
2. **插不上手**：想对某一个子任务说一句话（「这个方向不对」），没有入口，只能 `/ceo 停` 全停。
3. **CEO 拿不准时只会问一次**：问人是整个任务停下来等；董事长回一句后 CEO 再复核，没有「批准 / 驳回 / 改一下」这种一键回答。
4. **入口难找**：要先自己建群、拉机器人、发 `/ceo 群`，菜单里没有。
5. **结果散落**：交付是一条长消息，子任务产出的文档 / 文件没有汇总的地方。

## 二、设计原则

- **阶段一是地基**：CEO 只用阶段一已有的能力（开会话、建群、发话、插话、停下、模型、权限、群推送），不另建执行通道。阶段一的改动不阻塞阶段二，反之亦然。
- **董事长只跟 CEO 说话**：子任务群可以看、可以插话，但默认不用进去。
- **只在需要人时打扰人**：和阶段一的群推送同一个口径——需要人拍板一定推；重要进展推一条；普通过程不推。
- **少即是多**：董事长要记的只有一个入口（菜单「🧭 CEO」）和群里直接说话。

## 三、用户流程

### 1. 下任务
- 菜单「🧭 CEO」→ 一张卡：任务（输入框）、项目（下拉，可多选）、预算（下拉：快 / 均衡 / 深入，对应子任务数、模型档位、最多几轮）。回车即开。
- 自动建一个 CEO 群 `SN·CEO·任务短名`，董事长和机器人在里面；私聊只留一条「进群」。
- 已有的 `/ceo 群`（把现有群设成 CEO 群）保留，给已经建好群的人用。

### 2. 看分工、改分工
- CEO 拆完后在 CEO 群里发一张**任务看板卡**（置顶）：每个子任务一行：标题、工具 · 模型、状态（排队 / 在跑 / 等你 / 完成 / 失败）、「进群」按钮。
- 卡底两个按钮：「开工」「改一下」。默认 30 秒没人动就自动开工（预算选「快」时直接开工，不等）。
- 「改一下」= 在群里说一句「把 2 换成 Codex」「去掉 3」，CEO 重新拆。

### 3. 干活中
- 每个子任务**有自己的群** `SN·CEO·任务短名·子任务n`，复用阶段一的会话群：状态卡、插话、停下、模型、权限都现成可用。董事长默认不在里面也行（群成员只有机器人和董事长，董事长可以免打扰）。
- 看板卡原地刷新状态；子任务完成 / 失败 / 需要人时，CEO 群里各推一条短消息，带「进群看」按钮。
- 董事长在 CEO 群里说的话，CEO 判断是给 CEO 的（改目标、问进度）还是给某个子任务的（「告诉 2 号先别动数据库」），后者由 CEO 转发 / 插话到那个子任务。

### 4. CEO 要拍板
- 一张**决策卡**：问题一句话、背景两三行、2–3 个选项按钮 + 「我说一句」。选项由 CEO 给。
- 等人时只停住相关的子任务，其他继续跑。
- 卡片发出时 @董事长（不加急）；30 分钟没回复再 @ 一次，之后不再催。

### 5. 交付
- CEO 群里一张**交付卡**：结论三五行、每个子任务一行结果和链接、「查看完整报告」按钮。
- 完整报告写成一个飞书文档（复用阶段一的「导出文档」），链接放在卡上。
- 交付后子任务群自动标成「完成」，不解散；董事长说「再做一轮 xxx」，CEO 在同一个任务里接着派。

### 6. 管理
- 菜单「🧭 CEO」在私聊里点：列出进行中的 CEO 任务（每个一行：任务、进度、等你几件、「进群」）。
- CEO 群里：`停`（全部停）、`状态`（重发看板）；其余都用按钮。

## 四、不做的事（避免堆功能）

- 不做子任务之间直接互相通信：所有协调都过 CEO，董事长看得懂。
- 不做多层 CEO / 部门经理。
- 不让 CEO 自己去改权限、改全局默认模型。子任务权限跟随「飞书开的会话默认全部授权」，审批卡照常出在子任务群里，同时在 CEO 群里提一句。
- 不做定时 / 周期任务（阶段一的自动化够用）。

## 五、技术要点

| 项 | 做法 |
|---|---|
| 子任务开会话 + 建群 | 复用 `newsession` 的开会话 + 自动建群；群名加 `CEO·` 前缀，chatbind 里记 `mission_id` 和子任务号 |
| 看板卡 | 新卡，原地刷新（`update_multi`），和状态卡同一套 patch 逻辑 |
| 董事长对子任务说话 | CEO 大脑多一个 `route` 输出：`{"to": "ceo" \| n, "text": ...}`；给子任务的走 `control.steer`（在跑）或 `control.send`（空闲） |
| 决策卡 | 复核 schema 增加 `options: [str]`；按钮回调回到 `Orchestrator.answer()` |
| 只停相关子任务 | 复核 schema 增加 `blocked: [n]`；只有这些子任务挂起 |
| 子任务进展进 CEO 群 | 复用 `grouppush` 的判定（需要人 / 重要进展），目标多一个 CEO 群 |
| 预算 | 快：≤2 子任务、sonnet/luna、1 轮；均衡：≤3、默认模型、2 轮；深入：≤4、opus/sol、3 轮 |
| 报告文档 | 复用阶段一导出文档；交付卡带链接 |
| 重启恢复 | 现有 `interrupted` + 「继续」保留；看板卡显示「被重启打断，点继续」 |

## 六、版本拆分

| 版本 | 内容 | 验收要点 |
|---|---|---|
| 2.0.0 | 菜单「🧭 CEO」+ 下任务卡 + 自动建 CEO 群 + 看板卡 + 子任务各自建群 + 交付卡 | 一句话任务从下达到交付全程只看 CEO 群就能跟上；子任务群可进、可插话 |
| 2.1.0 | 决策卡（选项按钮）+ 只停相关子任务 + 30 分钟再提醒 | CEO 拿不准时一键回答；其他子任务不受影响 |
| 2.2.0 | 董事长在 CEO 群里对子任务说话（CEO 转发 / 插话） | 「告诉 2 号…」能准确送到 2 号 |
| 2.3.0 | 完整报告文档 + 私聊里的 CEO 任务列表 | 交付卡上能打开报告；私聊能看到所有进行中的任务 |

## 七、验收用例（CEO-01 ~ CEO-12，2.0.0 起逐版补齐）

| 编号 | 场景 | 期望 |
|---|---|---|
| CEO-01 | 菜单「🧭 CEO」下一个两步任务 | 建 CEO 群；看板卡列出 2 个子任务；各自建群 |
| CEO-02 | 看板卡点「改一下」说「把 2 换成 Codex」 | 重新拆分，2 号工具变 Codex |
| CEO-03 | 子任务在跑 | 看板卡状态原地更新；CEO 群不刷屏 |
| CEO-04 | 子任务完成 | CEO 群一条短消息带「进群看」 |
| CEO-05 | 全部完成 | 交付卡：结论 + 每个子任务一行 |
| CEO-06 | 子任务需要审批 | 审批卡在子任务群；CEO 群提一句并 @董事长 |
| CEO-07 | CEO 拿不准 | 决策卡带 2–3 个选项；点一个后继续（2.1.0） |
| CEO-08 | 等决策时 | 其他子任务继续跑（2.1.0） |
| CEO-09 | 在 CEO 群说「告诉 1 号先别提交」 | 1 号收到这句（在跑就插话）（2.2.0） |
| CEO-10 | CEO 群发「停」 | 所有子任务停下，看板卡显示已停 |
| CEO-11 | 服务重启 | 看板卡显示被打断；点继续接着复核 |
| CEO-12 | 阶段一回归 | 阶段一 13 条真机回归全过，阶段一功能不受影响 |
