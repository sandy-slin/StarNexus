# StarNexus 1.9.4 用户操作梳理

以「我拿着手机，想让电脑上的 Claude / Codex 干活」为主线，把当前版本能做的事按使用顺序过一遍。每一处都回答三个问题：用户在哪里点、点完会怎样、是不是多余。

数据来源：当前代码（main 99640ba）、`~/.carher-feishu-agent/logs/agent.log` 里的真实点击次数（11-13 到 11-19）。

## 一、用户真正在做的事

日志里的真实使用量：

| 操作 | 次数 | 说明 |
|---|---|---|
| 在会话群里说话（转发给会话） | 176 | Codex 100、Claude 70、opencode 6。这是主业务 |
| 新建会话成功 | 118 | 大部分来自回归测试，真人约 20 次 |
| 会话总览里点「接着聊 / 看看它 / 进群」 | 52 | send 24、open 20、go 8 |
| 审批卡点同意 | 31 | 1.9.1 之后全授权下大幅减少 |
| 常驻菜单「会话总览」 | 22 | 菜单里最常用 |
| 常驻菜单「模型」 | 16 | 第二常用 |
| 常驻菜单「新建会话」 | 7 | |
| 常驻菜单「全部按钮」「最近」「换项目」「权限」「停下」 | 4 / 4 / 3 / 2 / 1 | 低频 |
| 状态卡按钮（完成 / 刷新 / 导出 / 复制 / 归档） | 各 0–1 次 | 几乎没人点 |

结论：用户的路径集中在 **开会话 → 进群说话 → 偶尔看总览 / 换模型**。其余入口都是低频，应该收起来，而不是并排摆出来。

## 二、按使用流程逐步梳理

### 1. 开一个新会话

- 入口：菜单「🖥 会话 → ➕ 新建会话」、`/ns`、私聊说「新建会话」。三个入口打开同一张卡，这是对的。
- 卡片：工具、项目（下拉 + 输入框）、模型、强度、第一句话，回车即开，自动建群 `SN·工具·项目`，私聊只留一条「进群」。
- 评价：好用，是现在最顺的一条路。
- 问题：
  - 项目下拉、项目输入框、会话名三处是林森 11-18 定的（输入框和下拉联动，会话名按项目目录给推荐值），保留。卡上缺一句说明，第一次用会犹豫。**建议**：输入框的占位文字写清楚「选上面的项目，或输入新名字新建」，会话名预填好，用户不改也能直接回车。
  - 一句话开法 `/ns 工具 项目 模型 强度 第一句` 参数顺序靠记忆，实际只在回归测试里用。**建议**：保留但不在任何卡片上宣传。

### 2. 找到一个已有的会话接着聊

- 入口：菜单「🖥 会话 → 📋 会话总览」、`/find 关键字`、群里点「🔀 换个会话」。
- 总览卡列出电脑上所有 Claude / Codex / opencode 会话，每个有「接着聊」「看看它」，已建群的直接跳群。
- 问题：
  - 会话多了以后总览很长，要点「还有 N 个」展开；`/find` 能解决，但卡上没有搜索框。**建议**：总览卡顶部放一个输入框，输入关键字就是 `/find`；同时只默认列最近 8 个。
  - 「接着聊」「看看它在干什么」「看看它现在」「👀 看看它」四种叫法指同两件事。**建议**：统一成两个词：「进群」（有群就跳、没群就建）和「看一眼」。
  - 在私聊里也能「接着聊」（5 分钟对话模式），与「一个会话一个群」的主路线重叠，用户容易分不清自己在跟谁说话。**建议**：私聊里点任何会话都直接进群，私聊对话模式只给没法建群时兜底。

### 3. 在会话群里干活

- 直接说话就转给会话；一轮在跑时再说一句会插进这一轮（Claude、Codex、opencode 都支持）。
- 置顶状态卡：工具、模型、项目、状态、最近进展，下面 7 个按钮（模型、停下、完成、刷新、导出文档、复制会话、归档）+ 权限下拉 + 快捷命令一行。
- 群推送：只推需要人介入和重要进展。
- 问题：
  - 状态卡 7 个按钮，日志里除了「停下」「模型」，其余每个 0–1 次。**建议**：卡上只留「⏹ 停下」「🧠 模型」「权限下拉」，其余 5 个收进一个「更多」下拉（完成、刷新、导出、复制、归档）。刷新其实不需要：卡片本来会自动更新。
  - 卡底「快捷命令」一行和 `/m` 卡上的又重复一次。**建议**：卡上只留一句「不知道怎么做就发 /m」。
  - 每条回复后面都挂「🗣 正在和 X 说话…要退出就点退出对话」，在会话群里是噪音（群本来就只对一个会话）。**建议**：会话群里去掉这行，只在私聊对话模式里保留。

### 4. 换模型

- 入口：菜单「🧠 模型」（改默认）、状态卡「🧠 模型」（改这个会话）、新建卡上选。
- 评价：16 次点击，是常用功能，两层（默认 / 本会话）的区分是对的。
- 问题：菜单「🧠 模型」在会话群里点，改的是默认还是这个会话，标题要写清楚。**建议**：在会话群里点菜单模型，直接打开「这个会话」的模型卡，卡底一个链接「改默认模型」。

### 5. 权限

- 全局三档（只读 / 可写 / 全部授权），会话可单独设；飞书开的会话默认全部授权；`/p r|w|f`。
- 全部授权下只有推代码、提权、读密钥、删除脚本会出审批卡；删家目录始终拒绝。
- 问题：入口有菜单「⚡ 常用 → 🔑 权限」、`/m` 卡上的全局权限下拉、状态卡权限下拉、`/p`、`/mode`。**建议**：全局权限只放 `/m` 卡；会话权限只放状态卡；菜单里的「🔑 权限」去掉（2 次点击）。`/mode` 作为老命令保留但不宣传。

### 6. 停下

- 菜单「⏹ 停下」、状态卡「停下」、`/stop`。能停桥自己起的；终端 / App 里开着的会说明只能在那边停。
- 评价：清楚，保留。

### 7. 其他

- 「🌐 网页版」链接、「📂 换项目」、「↑ 最近问过」、「常用问题」6 条、「🩺 运行诊断」「⬆️ 版本和更新」「🆕 新话题」「ℹ️ 现在状态」：都是私聊里「机器人自己跑 Claude」那条老路的功能。用户现在主要用会话群，这些都是低频。
- **建议**：全部收进 `/m` 卡的「更多」下拉，不在常驻菜单单独占位。

## 三、建议的最终形态

### 常驻菜单（4 个，原来 5 主 5 子）

| 菜单 | 点了做什么 |
|---|---|
| ➕ 新建会话 | 打开一张卡，回车即开、自动建群 |
| 📋 会话 | 会话总览，顶部可搜索，点会话直接进群 |
| 🧠 模型 | 在会话群里改这个会话；在私聊里改默认 |
| ⏹ 停下 | 停当前上下文里在跑的那一轮 |

去掉「⚡ 常用」这一级（权限、换项目、网页版、全部按钮）：权限进 `/m` 和状态卡，其余进 `/m 更多`。阶段二上线后，再加第 5 个「🧭 CEO」。

### `/m` 卡

一张卡讲完：会话总览、新建会话两个大按钮；默认模型一行下拉；全局权限一行下拉；「更多」一个下拉（换项目、网页版、最近问过、常用问题、状态、诊断、版本、帮助）。

### 会话群状态卡

一行信息（工具 · 模型 · 项目 · 状态），最近进展一行；按钮只有「停下」「模型」；权限下拉；「更多」下拉。

### 要删 / 合并的叫法

| 现在 | 统一成 |
|---|---|
| 接着聊、接着跟它聊、确认开始说话、进群接着说 | 进群 |
| 看看它、看看它现在、看看它在干什么 | 看一眼 |
| 会话总览（含历史）、看看会话、回到总览 | 会话 |
| 退出对话、解绑这个群 | 解绑（只在群里出现） |

## 四、改动优先级

1. 状态卡瘦身（7 → 2 个按钮 + 更多），会话群去掉每条回复后的「正在和 X 说话」。改动小、每天都看得到。
2. 常驻菜单 5 → 4，去掉「⚡ 常用」；菜单「模型」在群里直接改本会话。
3. 统一按钮叫法（进群 / 看一眼 / 会话 / 解绑）。
4. 会话总览加搜索、默认只列最近 8 个；私聊点会话直接进群。
5. 新建卡：补输入框说明，会话名预填，不改也能直接回车。

每一项都按 dev-release 流程单独出 `1.10.x`，每项都配真机回归和 Computer Use 客户端核对。
