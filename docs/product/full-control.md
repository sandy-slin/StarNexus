# StarNexus 用户控制能力定义：在飞书里完全控制 Claude 和 Codex

> 版本：2026-11-16 v1。范围：阶段一（本地 Agent 遥控），同时给出阶段二（董事长 / CEO）的依赖。状态口径：已有 / 部分已有 / 未实现。标 🔴 的条目需要林森拍板或事后关注。

## 1. 目标

用户不在电脑前时，通过飞书完成在终端里能对 Claude 和 Codex 做的所有事：开会话、派任务、看进展、回答提问、批准操作、换模型、停下、收结果、找回旧会话。工具范围：首批 Claude 和 Codex；架构按可插拔设计，pi、opencode 等后续工具通过适配层接入，用户流程和交互不变。飞书不只是“手机上的终端”，还要用上它比终端强的地方：

| 飞书能力 | 在 StarNexus 里的用途 |
|-|-|
| 群 | 一个会话一个群，群就是会话的工作台，名字统一、可搜索 |
| 交互卡片 | 选择工具、模型、项目；回答提问；批准操作；停下 |
| 推送、@、加急 | 需要人介入时一定送达，普通进展不刷屏 |
| 群置顶 / 群公告 | 常驻显示会话的状态、模型、项目、权限 |
| 云文档 | 长结果、报告、方案作为交付物，不挤在聊天里 |
| 图片和文件消息 | 截图、日志、设计稿直接交给 Agent |
| 移动端 | 随时随地处理，审批和回答只要点一下 |

## 2. 设计原则

1. **同等控制**：手机和终端共用同一个权限档位，手机能做的事不比终端少。只保留一条硬红线：不删家目录（点同意也不执行）。读凭据、推代码（git push）、提权（sudo / su，或修改系统级权限拿到管理员权限）从硬拒绝改为逐次审批：Agent 先发审批卡，点同意后执行；凭据内容回到飞书前一律脱敏。
2. **一个会话一个群**：会话的所有交互都在它的群里完成。私聊只做入口和总览。
3. **工具可插拔，交互统一**：Claude 和 Codex 的菜单、卡片、文案一致，但工具集合可扩展：Claude 和 Codex 只是首批，pi、opencode 等通过适配层接入，交互层不变；底层差异由系统处理，做不到的事要说明原因和替代方法。
4. **只在需要时打扰**：需要人介入的一定推送并提醒；推送自带可决策上下文，不转述原始问题；重要进展推送；过程细节放在群里按需查看。
5. **默认可用，按需细调**：不指定就用默认模型和默认项目；会话级设置优先于默认设置。
6. **结果可交付**：长结果写成飞书文档，聊天里只放摘要和链接。

## 3. 统一用户流程

```
开始  → 新建会话（工具、项目、模型、第一句话）→ 自动建群
工作  → 群里说话 = 给会话下指令；可以发图片、文件
关注  → 群置顶状态卡；重要进展和完成结果推送到群
介入  → 提问 / 审批卡片在群里点选；需要人介入时 @ 本人并加急
调整  → 换模型、换 effort、换权限、停下、继续
收尾  → 结果摘要 + 飞书文档；归档会话、解散或保留群
找回  → 会话总览 / 搜索 → 点一下回到对应群
```

## 5. 功能定义

### 5.1 新建会话

- **入口**：常驻菜单“🖥 会话 › ➕ 新建会话”；命令 `/ns 工具 项目 [模型] 第一句话`；私聊说“新建会话”。
- **输入**：工具（必选，来自已接入工具列表；首批 Claude / Codex）；项目（白名单和最近项目，必选）；模型（可选，默认取该工具的默认模型）；effort（可选）；第一句话（必填）。
- **新建项目**：项目选择器最后一项 `➕ 新建项目`；命令 `/ns project new <路径> [--git]`。输入项目名、路径（必须落在预配置的项目根目录下，如 `~/projects`）、是否 `git init`。行为：校验路径不越界、不覆盖已有目录 → 建目录 → 可选 `git init` 并打初始 commit → 写入白名单（来源=用户创建）→ 刷新项目列表并预选。边界：禁止 `..` 逃逸和系统目录；删除项目只在飞书里“移出白名单”，不删磁盘。
- **行为**：创建会话，建群，绑定群和会话，把第一句话发进会话，在群里置顶状态卡，私聊回一张带“进群”按钮的卡片。
- **群名规范**：`SN·工具·项目·标题`，例如 `SN·Codex·remote_control·修登录`。前缀 `SN` 用于在飞书里搜索全部会话群；重名时加短 id。
- **现状**：已有（2026-11-17）。建群、绑定、第一句话、`SN·` 群名前缀、置顶状态卡、模型和 effort、新建项目都已实现。新建项目：`/ns project new <完整路径> [--git] [claude|codex]`，只能建在白名单根目录下（最多 4 层），不覆盖已有目录，不建在隐藏目录或系统目录；带 `--git` 时 `git init` 并做一个空的初始提交；带工具名就直接进第一句，否则接着选工具并直接用这个项目。白名单就是根目录，新项目建好即可用，不改配置。

### 5.2 群里工作

- 群里任何一句话都发给绑定的会话，不需要 @ 机器人。
- 发送状态分三步显示：已发送 → 已送达 → 正在回复。
- 进展卡持续更新，同一轮只占一条消息，不刷屏。
- 图片和文件保存到 `项目/.starnexus/inbox/`，并把文件路径附在消息里发给 Agent。
- **现状**：已有（2026-11-17）。文字转发、最终回复、进展卡原地更新（FC-14）、图片和文件输入（FC-09）。主人在已绑定的会话群里说话直接进会话，不再弹“确认，开始说话”卡（da90e6e）。发送三步：一发出就贴一张卡“✅ 已发送 → ⏳ 已送达 → ⚪ 正在回复”，会话记录里出现这句后改成已送达，出现第一条推理、工具调用或回复后改成正在回复；全程只改这一张，等久了同一张卡接着显示进展。

### 5.3 回答提问和批准操作

- Agent 提问时，群里出现问题卡：题目、选项按钮、“补充说明”输入框。点选后，答案作为会话的输入继续这一轮。
- Agent 要做超出档位的操作时，群里出现审批卡：操作内容（已脱敏）、风险说明，以及三个按钮：同意这一次 / 这个会话都同意 / 拒绝。Codex 切到 danger-full-access 后，工作区内默认直接执行；审批只覆盖工作区以外目录的改动，以及读凭据、git push、提权三类逐次审批操作；删家目录不可审批。
- 两类卡片都算“需要人介入”：立即推送并 @ 本人；10 分钟未处理再加急一次。
- 卡片自带背景摘要：现状、为什么需要你定、选项与建议、不处理后果。摘要由 Agent 写，原始输出留在群里按需展开。
- **现状**：已有（2026-11-17）。回复里的编号选项变成按钮（FC-07）；群会话审批卡并 @ 本人（FC-06）；需要人介入的推送带“现状 / 卡在 / 你可以 / 不处理”四段（65c2bde）。“补充说明”输入框暂不做，直接在群里打字回答代替。🔴 Codex 没有会话中途的审批回传：被拦下的一步先拒绝，批准后重跑。

### 5.4 模型和 effort

- **默认模型**：每个已接入工具各存一份默认模型和默认 effort。入口在“🧠 模型 › 默认模型”，先选工具，再选模型和强度。
- **会话模型**：在会话群里点“🧠 模型”，修改这个会话的模型，从下一轮开始生效。修改后状态卡同步更新。
- 模型列表从本机配置读取，不在代码里写死。
- **现状**：已有（2026-11-17）。默认模型按工具分别设置，会话可单独换模型和 effort，下一轮生效（FC-04/05）；opencode 没有 effort。状态卡在没指定模型时写出工具自己配置的实际模型，例如“工具默认（claude-opus-5-5 / 极限）”（282be19）。

### 5.5 停下和继续

- 群里的“⏹ 停下”只停这个会话当前这一轮，不关闭会话。
- 手机发起的一轮可以直接停。电脑终端或 App 正在跑的一轮，按工具能力处理；做不到时说明原因，并提供“提醒我到电脑上停”。
- 私聊里的“停下”列出所有正在跑的会话，用户选择要停哪个。
- **现状**：已有（2026-11-17）。私聊“停下”列出正在跑的会话：手机发起的一轮给“⏹ 停”，停后会话保留；终端 / App 里的一轮说明原因，并给“⏰ 提醒我到电脑上停”（10 分钟后仍在跑就私聊提醒）和“👀 看看它”。🔴 Claude 终端会话收到 SIGINT 会整个退出，所以终端里的一轮停不了；Codex 停止终端里的一轮需要用 App 私有协议，目前按设计不做。

### 5.6 结果交付和收尾

- 一轮结束时，群里发结果摘要。超过 1500 字，或包含报告、方案类内容时，自动写成飞书文档，群里只发摘要和文档链接。
- 会话收尾：标记完成，群名加 `✅` 前缀，状态卡改为已完成；用户可以选择归档会话。
- 解散群（决定 2026-11-17）：解散是不可逆的外部动作，机器人不代办。主人本来就是群主，归档时提示他在群设置里自己解散；不解散时群和聊天记录都保留。
- **现状**：已有（2026-11-17）。超过 1500 字自动写飞书文档（FC-10）；状态卡“✅ 完成”给群名加 ✅ 前缀、状态卡变绿，“↩︎ 重新打开”去掉前缀；主人自己改过的群名不动。归档已有（bd04677）：Codex 用 `codex archive`，Claude 记为结束，群名加 ✅，并提示主人自己解散群（604c29f）。

### 5.7 找回会话

- 会话总览列出所有已接入工具的会话（首批 Claude 和 Codex），按“需要我处理 / 正在跑 / 最近完成 / 更早”排序。
- 点会话：有群就直接进群，没有群就建群（重复点击不会建第二个群）。
- 支持按项目、标题和关键字搜索。
- **现状**：已有（2026-11-17）。总览按“等你 > 在跑 > 其余按最近更新”排序；点会话有群直接进群，没群就建（FC-03）；`/find 关键字` 或“找会话 关键字”按标题、项目、编号搜索，多个词都要命中，结果按钮直接进群。

### 5.8 推送策略

| 事件 | 推送 | 提醒方式 |
|-|-|-|
| 提问、审批、等待输入 | 必推 | @ 本人；10 分钟未处理再加急 |
| 出错失败 | 必推 | @ 本人 |
| 一轮完成 | 推摘要 | 普通消息 |
| 重要进展（计划确定、阶段完成、产出文档） | 推一句 | 普通消息，同一会话 10 分钟最多一条 |
| 工具调用和中间输出 | 不推 | 只更新进展卡 |

**现状**：已有（2026-11-17）。等待 / 完成 / 失败三类推送、@ 本人、10 分钟加急（权限未开通时退化成文字提醒）、1 小时后再提醒、重要进展识别（计划 / 阶段完成 / 产出文档等短句，同一会话 10 分钟最多一条）都已实现。

### 5.9 工具接入（适配层）

- **定位**：Claude 和 Codex 是首批接入的两个工具，不是架构上限。新增工具（pi、opencode 等）通过适配层接入，菜单、卡片、群、推送、状态卡都不变。
- **适配接口**：每个工具实现同一组能力——会话（新建、恢复、发送、停止、状态查询）、事件（进展、提问、审批、完成、失败，统一成一套事件模型）、配置（模型列表、effort、权限档位、项目目录）、交付（结果文本、产物文件、长结果）。
- **能力声明**：每个工具声明自己支持的能力和限制；不支持的项在菜单和卡片里隐藏或置灰，并给出替代方法。§4 的矩阵按工具逐列展开。
- **最小接入验收**：能建会话、发一句话、看到一轮完成、能停下；再按 §4 矩阵补齐提问、审批、模型、权限等项。
- **边界**：工具私有协议不进交互层；工具升级导致接口变化时，只改对应适配器，并跑同一套验收用例。
- **现状**：已有（2026-11-17）。能力声明表在 `bridge/fleet/model.py` 的 `CAPS`（start / send / stop / fork / archive / model / effort / approval / progress / choices），菜单、新建会话卡、模型卡按它显示。第三个工具 opencode 已接入（`bridge/fleet/opencode.py`）：新建、接着聊、停下、复制、模型列表；真实飞书验收通过（私聊 `/ns opencode` → 写文件 → 自动建群 → 群里接着问能答对）。opencode 不支持：逐条审批（档位 trusted / write 用 `--auto`）、effort、进展卡里的工具列表。
- **实测坑**：opencode 认环境变量 `PWD` 而不是子进程 cwd；要加 `--standalone` 才按指定目录工作；本机自带默认模型（grok-4.6）一次工具调用要几分钟，默认改用 `cpa-gui/gpt-5.6-luna`（可用 `CARHER_OPENCODE_MODEL` 换）；后台服务 PATH 会先找到旧版 `~/.local/bin/opencode`（1.18），现在自动挑最新版本。

## 6. 菜单定义

**私聊常驻菜单（全局）**：🖥 会话（新建 / 总览 / 搜索）、🧠 模型（按工具设置默认）、⚡ 常用（权限 / 项目 / 网页版 / 全部按钮）、⏹ 停下（选择会话）。

**会话群卡片（会话级）**：状态卡上放 💬 继续、🧠 模型、⏹ 停下、📄 导出文档、✅ 完成，以及更多（重命名 / 归档 / 复制会话）。

飞书的常驻菜单对所有聊天都相同。所以会话级操作放在群置顶状态卡上，私聊菜单只放全局操作。

## 9. 需要林森关注

Codex 的 trusted 档位（2026-11-16 已拍板）：需要把 trusted 改成 danger-full-access，已采纳。只保留一条缺省约束：工作区以外的目录不可更改；确需更改时，由会话向林森提出请求，获批后执行。网络不再受沙箱限制；硬红线按原则 1 收窄，只剩“不删家目录”。

停止电脑上正在跑的一轮：Claude 终端会话收到中断信号会整个退出；Codex 需要用 App 私有协议。这两种情况本版只做说明和提醒，不强行停止。

Codex 中途审批：需要先做技术验证。不可行时，Codex 只能依赖档位，没有逐条审批卡。

群名前缀 SN·：新建群直接用 `SN·工具·项目·标题`。旧群（2026-11-17 调整）：服务启动时自动补上 `SN·` 前缀，只改我们起的、没人动过的群名；你自己改过名的群不碰。这样飞书里搜 `SN·` 能列出全部会话群（FC-15）。

工具扩展：Claude 和 Codex 是首批适配对象，交互层不绑定具体工具。第三个工具接入前先完成适配层抽象，否则每加一个工具都要改一遍卡片和菜单。

硬红线收窄（2026-11-16 按评论调整）：只保留“不删家目录”。读凭据、git push、提权（sudo / su、修改系统级权限）改为逐次审批，点同意后执行。这会放宽现有代码的拦截，实现时需要同步改 policy.py 的拒绝清单和对应测试。

新建项目默认进白名单（已决定）：在项目根目录内新建的项目自动写入白名单，来源标记为“用户创建”，不设待审环节。路径越界、系统目录和已有目录仍然拒绝；不需要时在飞书里移出白名单即可。

第三个工具先接 opencode（已决定）：本机已安装 opencode 和 pi。opencode 的 run 命令支持 JSON 输出、按 id 续接会话、指定模型和自动批准，和现有 Claude / Codex 的非交互调用方式最接近，适配成本最低；pi 随后接入。
