# 飞书常驻菜单更新

菜单修改必须分别验证源码、飞书能力配置、应用版本和客户端缓存。

## 修改前

- 先读 `bridge/botmenu.py` 文件头和 `bridge/menu_heal.py`。
- 菜单总节点上限是 10，父子节点合计；悬浮菜单主菜单最多 5 个，单父菜单最多 5 个子菜单。
- 修改后运行 `validate_tree()`，返回空列表才继续。
- 菜单形状变化会改变指纹，必须发布新版本。菜单点击事件和卡片回调必须一起订阅。

## 版本和发布

- 飞书版本号必须是 `X.Y.Z` 数字形式，不能有前导零。统一使用 `bridge.botmenu.version_for_time()`。
- 禁止恢复 `1.%Y%m%d.%H%M%S`：它可能生成 `1.20261116.062900`，触发 `50516 invalid request`。
- 发布顺序：写菜单能力 → 订阅事件和回调 → 生成版本 → 提交版本 → 确认后台状态。
- 只有菜单写入、订阅和版本提交均成功，才记录 `menu_heal.json` 的 `done: true`。
- 看到 `50516` 先检查版本格式和后台版本状态，不要重复改菜单树或把重启当发布成功。

## 客户端验收

服务端发布成功后，仍需在目标飞书私聊中看到实际菜单，例如：

```text
🖥 会话   ➕ 新建会话   🧠 模型   ⚡ 常用   ⏹ 停下
```

客户端画面未读到时，只能记录“服务端已发布，客户端待确认”。
