# StarNexus（星枢）菜单产品定义（第一版：常驻 Bot 菜单）

## 产品总定义

**StarNexus（星枢）**是一个本地 AI Agent 编排系统：董事长提出总目标，CEO 负责拆解、分配、仲裁和汇总，Claude、Codex 等 Agent Session 在本地电脑上执行子任务，飞书负责移动端入口、过程沟通、群绑定和结果回传。

系统角色关系：

- **董事长 / 人：**提出目标、关注整体进展，并在需要时做关键决策。
- **CEO / 编排中枢：**拆分总任务、选择 Agent 和模型、协调 Session、汇总结果、继续派发指令，并向人发起决策请求。
- **Agent Session / 执行单元：**由 Claude、Codex 等工具承载，负责具体子任务的读写、执行、分析和交付。
- **Her Remote：**当前通过飞书控制本地电脑的运行实例和连接层，不是 StarNexus 的全部产品定义。

产品主链路：

董事长目标 → CEO 拆解与编排 → Agent Session 执行 → 群内进展与异常 → CEO 汇总 → 董事长结果 / 决策

后续菜单、会话、模型和群能力都以这个角色关系为上位产品语境；本文下面的“已有 / 部分已有 / 未实现”只描述当前代码状态，不代表 StarNexus 已经完整实现全部愿景。

> 本版只定义常驻 Bot 菜单，不修改对话内“全部按钮”卡片。状态口径：已有、部分已有、未实现。

## 先看结论

常驻菜单按用户任务流聚合为四个主入口和一个紧急操作：

- **🖥 会话**：新建会话、会话总览、历史会话的统一入口。
- **🧠 模型**：当前主要是设置默认模型；Claude / Codex 分模型和 effort 还没有完成。
- **⚡ 常用**：权限、项目、网页版和全部按钮。
- **⏹ 停下**：停止当前聊天上下文中正在执行的任务；跨会话停止从会话详情进入。

菜单结构已经按这套分组发布并通过 Computer Use 验收；下面记录功能层面的差距。

## 统一使用流程

1. **创建**：进入“会话”→“新建会话”，选择工具、项目、可选模型，再发送第一句话。
2. **找回**：进入“会话”→“会话总览”，看到 Claude 和 Codex 会话列表；点击一个会话进入详情。
3. **进入群**：已有绑定群就直接打开；没有绑定群就创建并绑定。
4. **继续工作**：群内消息进入对应会话，使用当前权限档位，并保留工作区白名单、审批钩子和硬性拒绝规则。
5. **调模型**：“模型”设置默认值；具体会话详情中切换该会话模型。模型列表区分 Claude / Codex，并显示模型支持的 effort。
6. **停止**：常驻菜单停止当前任务；会话详情停止指定会话任务。

## 🖥 会话：新建与找回

### 新建会话是什么动作

新建会话是“创建新的本机 Agent 工作上下文”，不是简单发送一条消息。

| 输入 | 定义 | 当前状态 |
|---|---|---|
| 工具 | Claude 或 Codex | 已有 |
| 项目 | 从工作区白名单和最近项目选择，越界拒绝 | 已有 |
| 模型 | 可选；未指定时使用该工具默认模型 | 部分已有：有别名和保存逻辑，但默认模型尚未按工具分层 |
| 第一句话 | 创建完成后作为新会话第一条任务输入 | 已有 |
| 权限档位 | 跟随当前权限档位；trusted 默认允许工作区内完整控制 | 已有 |

**预期行为：**创建本机会话 → 写入第一句话 → 返回首轮结果 → 自动建立并绑定对应群 → 后续消息进入同一个会话和群。

**当前 Gap：**新建链路能选择 Claude / Codex、项目和模型，但模型列表按工具分层和 effort 选择尚未实现。

### 会话总览

**产品定义：**会话总览是所有可管理会话的统一入口。第一版范围列出 Claude 和 Codex；Cursor 不进入新建入口，是否继续在历史总览展示需要明确。

**当前已有：**Fleet 总览、按工具分组、状态、项目、标题、更新时间和详情卡；Computer Use 已看到 Claude、Codex、Cursor 分组。

**当前 Gap：**用户要求“列出 Codex 和 Claude 所有会话”，现状仍可能展示 Cursor，需要在总览层明确过滤规则。

### 点击一个会话

| 情况 | 预期行为 | 当前状态 |
|---|---|---|
| 已经建群 | 直接打开绑定群，不新建重复群 | 已有：详情卡已有群直达链接和绑定复用逻辑 |
| 没有建群 | 点击会话即创建群、绑定当前会话并打开新群 | 部分已有：当前通常要再点一次“接着聊” |
| 群内权限 | 群消息进入对应会话；具备当前档位的读写执行能力，边界规则继续生效 | 已有 |

**核心 Gap：**当前“点击列表行 → 详情 → 再点接着聊”比目标多一步。需要把建群前移到会话选择确认阶段，并保证幂等。

## 🧠 模型：默认模型与会话模型

### 默认模型

默认模型是未指定模型的新会话使用的模型，必须按工具分别保存：

- Claude 默认模型：从 Claude 模型列表选择。
- Codex 默认模型：从 Codex 模型列表选择。
- 修改默认模型只影响以后新建的会话，不追溯修改已有会话。

**当前状态：部分已有。**当前有“均衡 / 最聪明 / 最快 / 稳”四个按钮并能保存默认模型，但模型选项主要来自统一的 Claude `MODEL_CHOICES`；新建会话另有 Claude / Codex 别名表，模型体系没有统一。

**Gap：**模型列表要按 Claude / Codex 分组，默认值保存为“工具 → 模型”，不能用一个全局模型字段覆盖两套工具。

### 指定会话切换模型

**产品定义：**在会话详情选择“模型”，先显示当前工具，只列该工具可用模型；选择后只影响当前会话，后续继续对话沿用该模型。

**当前状态：未实现。**详情卡有继续聊、停下、刷新等操作，没有会话级模型切换和持久绑定。

### 模型强度 / effort

**产品定义：**模型决定使用哪一个模型，effort 决定该模型投入多少推理资源。只有模型声明支持 effort 时才显示。

**当前状态：未实现。**当前模型卡只有四个按钮，没有 effort 维度，也没有按模型能力动态显示和校验。

## ⚡ 常用

| 入口 | 产品定义 | 当前状态 |
|---|---|---|
| 🔑 权限 | 查看并切换档位；trusted / write / readonly 受本机上限约束，放开需要二次确认 | 已有 |
| 📂 换项目 | 切换桥自身工作目录；切换后新开桥会话，不复用原项目上下文 | 已有 |
| 🌐 网页版 | 直接打开网页版，不经过本机 Agent | 已有 |
| 全部按钮 | 承载低频问题、状态、历史和其他操作 | 部分已有，待重构 |

整理原则：常驻菜单只放高频任务；全部按钮承载低频和诊断；同一动作只保留一个主入口，其他位置只提供上下文快捷按钮。

## ⏹ 停下

**产品定义：**“停下”停止当前正在执行的一轮，不退出会话、不删除会话、不撤回已经进入队列的消息。

- 常驻菜单点击：停止当前聊天上下文正在运行的任务。
- 会话详情点击：停止被选中的具体会话任务。
- 没有可停止任务：明确提示当前没有运行任务。
- 停止后会话保留，可以从会话详情继续聊。

**当前状态：部分已有。**常驻 `/stop`、详情卡停止和会话级停止已有，但常驻按钮目标是当前聊天，不是刚刚浏览的任意会话；产品文案和目标范围需要明确区分。

## Gap 清单与下一步

1. **P0 点击会话即进群：**已有群直接打开；无群时幂等创建并打开，减少一次“接着聊”。
2. **P0 会话范围：**总览默认只列 Claude / Codex；明确 Cursor 历史会话是否隐藏。
3. **P1 模型分层：**建立 Claude 模型目录和 Codex 模型目录，默认模型按工具分别保存。
4. **P1 会话模型：**详情卡增加“切换模型”，只影响当前会话并持久化绑定。
5. **P1 effort：**按模型能力显示 effort，保存到会话级配置，并在启动 / 继续时传给对应工具。
6. **P2 对话内菜单：**下一轮按同一用户流程重构 `/menu` 卡片，去掉与常驻菜单重复的平级入口。

**本版结论：**以上 Gap 是基于当前代码的产品定义和差距识别，本轮没有实现这些 Gap。
